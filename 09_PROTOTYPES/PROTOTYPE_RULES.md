# NEWMODEL — Prototype Rules
Version: 1.0
Status: ACCEPTED AS WORKING METHOD

## Prototype purpose
A prototype is primarily an instrument for discovering:
- product identity;
- user understanding;
- missing requirements;
- interaction problems;
- architectural constraints;
- decision quality.

## Visual-first
If a concept materially affects user understanding, visualize it before large implementation.

## Prototype boundary
A prototype may simplify:
- data;
- integrations;
- authentication;
- persistence;
- automation;
- calculations;

but must not misrepresent what is real versus simulated.

## Prototype labels
Where relevant, clearly mark:
- REAL
- SIMULATED
- ASSUMED
- DEMONSTRATION ONLY

## Vertical slice
Prefer one meaningful end-to-end scenario over many disconnected screens.

## Review questions
- Does the user understand the problem within seconds?
- Is the important decision visible?
- Are constraints visible?
- Are alternatives understandable?
- Is feasibility distinguishable from preference?
- Is the next action obvious?
- Does the visual model expose a missing requirement?

## Exit condition
Do not expand prototype scope merely because more screens can be built. Expand only when the current prototype has answered its intended question.
